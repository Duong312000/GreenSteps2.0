# GreenSteps Chatbot Bugs Reproduced from Workbook Cases

| Ticket | Reproduced issue | Fix | Evidence |
|---|---|---|---|
| GSCHAT-001 | Casual “muốn đi” requests produced an unfiltered catalog query; a destination after origin wording could be parsed as the origin. | Parse explicit requested destination and use a destination-filtered tour discovery response. | `INT-019`, `DEST-001`, `DEST-011`, `DEST-013` assertions in `greensteps-chat-workbook-regression.test.js`. |
| GSCHAT-002 | Structured AI tour references were accepted even when their destination differed from the request. | Canonicalize only catalog tour IDs matching the requested destination; replace mismatched-only answers with an honest no-match response. | `API-006` normalizer fixture assertion in `greensteps-chat-workbook-regression.test.js`. |
| GSCHAT-003 | Tour-result cards did not show a “Tự tạo lịch trình” action, including after destination discovery. | Add a compact action beside tour results; it sends the backend’s destination-aware itinerary suggestion. | `TOUR-001`, `UI-001`, `UI-003`, `CTX-005`, `CTX-006` local browser fixture flow. |
| GSCHAT-004 | Negative duration such as “-3 ngày” could be parsed as a positive day count; zero days was not rejected explicitly. | Ask again for a valid 1–14 day duration; cap supported itinerary length at 14 days. | `SLOT-008`, `SLOT-009` fixture assertions. |
| GSCHAT-005 | Alternative destinations joined by “hay/hoặc” could become a single invalid destination query instead of a clarification. | Leave ambiguous destination queries broad and ask the user to choose among catalog destinations. | `DEST-007` fixture assertion. |
| GSCHAT-006 | The word-boundary check for unaccented `o` could treat the final letter in “tạo” as a location preposition, causing an invalid destination. | Use Unicode-aware letter boundaries for `o`; constrain selected-destination parsing. | Existing catalog sentence-period parser test plus workbook slot/context fixture regression. |
| GSCHAT-007 | An active hidden service or a service of the wrong activity type could be marked verified. | Require visible active service ID, matching destination and compatible type; source verified fields from the catalog. | `VER-006`, `VER-030` fixture assertions. |
| GSCHAT-008 | The unaccented destination fallback matched the phrase “lịch trình” as if it were a destination in a clarification turn. | Require Unicode-aware boundaries for the standalone `o` preposition and keep the pending slot question as the state source. | `CTX-001`, `CTX-002`, `CTX-003` multi-turn fixture assertions. |
| GSCHAT-009 | P1 itinerary synonyms using “plan”, “itinerary”, “dựng”, “cần”, or “xếp lịch ăn chơi” were not consistently classified as itinerary creation. | Extend the normalized intent patterns for the workbook synonym phrases while keeping explicit tour search precedence. | Workbook source utterances `INT-003`–`INT-018` all pass the grouped classifier regression. |

| GSCHAT-010 | A direct tour question could include the final negative particle in the parsed destination and return a false no-match. | Strip a terminal Vietnamese question particle while preserving the requested place; keep the CTA on a completed empty result. | `queryFromRequest({ message: 'Có tour Đà Nẵng không?' })` returns `Đà Nẵng`; `TOUR-002` and `TOUR-023` fixture assertions. |
| GSCHAT-011 | A model response could use a different known destination in the itinerary title while its canonical destination field matched the request. | Reject proposals with conflicting known destinations in itinerary titles, day labels, or activity labels; return a safe correction and null itinerary. | `PLAN-020` regression failed before the fix and passes after it; fixture-only. |
| GSCHAT-012 | The “create itinerary” action text “ở card Đà Nẵng” was parsed with “card” as part of the destination. | Strip the UI noun prefix when parsing the destination from an explicit itinerary action, and ask for missing duration. | `TOUR-022` asserts destination `Đà Nẵng` and duration clarification before any itinerary generation. |
| GSCHAT-013 | Budget language without currency symbols and explicit per-person scope were not consistently retained in the catalog query. | Parse Vietnamese shorthand amounts and carry `budgetScope=per_person` through normalized catalog query metadata. | `SLOT-014`, `SLOT-035`; `node --test backend/test/greensteps-p0-closeout.test.js`. |
| GSCHAT-014 | A plan could silently combine a destination with a known cross-region attraction, or retain an explicitly excluded activity. | Clarify route conflicts and reject normalized proposals containing explicit exclusions. | `DEST-021`, `DEST-022`, `SLOT-027`, `PLAN-002`, `PLAN-003`, `PLAN-021`; closeout unit assertions. |
| GSCHAT-015 | Generic itinerary follow-up could lose destination context, while malformed JSON-like model output could be surfaced as raw text. | Preserve safe itinerary context for follow-up and reject malformed structured output. | `CTX-016`, `PLAN-025`; closeout unit assertions. |
| GSCHAT-016 | Inconsistent itinerary destination could render, and the UI did not distinguish verified services from reference activities. | Reject proposal destination mismatch in the frontend and label verified services separately from suggestions. | `UI-014`, `UI-017`, `UI-025`, `VER-020`; Angular fixture tests. |
| GSCHAT-017 | Model-supplied price/carbon claims could disagree with catalog values without a value-safe audit signal; cross-destination service mismatch was not explained. | Use catalog fields only, log mismatched field names without model values, clear invalid service IDs, and explain destination mismatch. | `VER-003`, `VER-011`; `node --test backend/test/greensteps-p0-closeout.test.js`. |
| SECURITY-BLOCKER-001 | A webhook credential was disclosed in the conversation; no evidence confirms revocation/rotation. | Rotate/revoke it in n8n and backend configuration, then verify through the approved secret-management process. Do not reuse or include the value in reports. | `SEC-020` remains BLOCKED. No production webhook request was sent with the disclosed credential. |

Tickets GSCHAT-001 through GSCHAT-017 have local fixes/assertions where listed; cases explicitly described as untested or blocked in `greensteps-351-test-results.csv` remain open for verification. These fixture results do not establish live MongoDB or n8n runtime behavior.
